# Compare downstream results

Use the five synthetic tasks in [outcomes.json](../tests/behavior/outcomes.json) to check usefulness separately from response-protocol compliance. They cover writing, summarization, structured extraction, coding instructions, and an advanced execution prompt. No private lab or new evaluation framework is needed.

1. Record the exact candidate, host/version/model, tools, resource limits, and the remaining shared [validation budget](testing.md#diagnose-failures-and-bound-the-work). Use the same conditions for both arms except YSAP availability. Exclude other skills and contributor instructions from both product sessions. Record unavoidable host instructions.
2. For each case, start two fresh conversations. Give each only `request`: one with the exact candidate available through native skill loading, one without YSAP. Do not force an invocation in the enabled arm. Verify source identity and record whether selection actually occurred; an unselected skill limits any attribution to YSAP.
3. Save each resulting prompt. Preserve questions or failures. If clarification is needed, supply the same factual answer to both arms where relevant, and retain the extra turns. Do not silently repair either output. If no usable prompt was produced, record that arm incomplete.
4. Run each produced prompt in a fresh downstream conversation, followed by the identical `downstream_input`, under the same host and model with YSAP absent in both. These are synthetic text tasks. The advanced case is a decision exercise, not a real autonomous run. Coding outputs may be checked in a disposable synthetic directory after inspecting the source for effects.
5. Randomize output labels and give a fresh reviewer the task, downstream input, criteria, and anonymized outputs. Withhold the mapping and generator commentary. Judge every criterion and record wins, ties, failures, or uncertainty before revealing the conditions. Do not use branded headings as a proxy for task quality.
6. Compare unnecessary questions, prompt and final-answer length, and measured end-to-end elapsed time from the retained transcripts. Count both stages and all failed attempts. Use deterministic JSON, word-count, or function checks where they establish an explicit requirement; use semantic review for usefulness and fidelity.

Keep prompts, raw transcripts, the label map, measurements, and review privately. Ask a human to calibrate a small sample or resolve disputed product judgments before treating AI preferences as settled. Record pending human calibration honestly; it need not block a behavioral release that makes no measured-superiority claim.

This small comparison describes its cases and conditions. A tie is useful evidence; a regression is retained. It is not statistical proof, broad host qualification, or permission to keep rerunning until the skill wins. Missing results limit claims. Report an unobserved arm as unverified, and keep behavior failures subject to the testing policy.
