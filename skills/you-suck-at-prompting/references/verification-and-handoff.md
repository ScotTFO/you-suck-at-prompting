# Verification and handoff

Read this reference only when the task needs task-specific evidence, a consequential handoff, staged or hard-to-reverse work, an unresolved risk or deviation, or a separately approved effect.

## Choose evidence

Name the smallest check that can establish the requested result. Use a test for behavior, a readback for file or record content, a comparison for a transformation, a confirmation or receipt for an external operation, and a visual inspection when layout or appearance is part of the deliverable. Inspect every requested page, view, or output when the artifact has multiple parts.

Confidence language is not evidence. Do not add a report, repeated inspection, or new approval gate when the request already names an adequate check or when the work is a routine direct action.

## Handoff report

For a consequential handoff, staged or hard-to-reverse work, unresolved risk or deviation, or a pending separate approval, report:

- the result or artifact location;
- the verification evidence;
- assumptions or deviations;
- unresolved risks; and
- actions awaiting separate approval.

Keep the report compact. Omit fields that have no material value for a routine direct task.

## Example

> Create the release note draft, compare every stated version against the supplied changelog, and report the draft path, comparison result, any discrepancies, and the separate approval still needed before publication.

Verification guidance changes the evidence requested in the prompt. It does not authorize publication, sending, deployment, purchase, deletion, disclosure, or permission changes.
